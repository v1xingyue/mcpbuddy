# MCPBuddy 产品介绍与未来规划

## 产品简介

MCPBuddy 是一个面向个人创作者和 AI 工作流的 MCP 连接中心。用户通过 GitHub 或 Google 登录后获得自己的受 OAuth 保护的 MCP 服务入口，并可在 Claude、ChatGPT（OpenAI）和 Grok 中连接该入口，安全地调用个人数据与工具。

产品的核心目标是：让用户只需维护一个 MCP 中心，就能在多个 AI 平台之间复用身份、工具和内容，而不必为每个平台分别搭建后端服务。

线上入口：<https://mcpbuddy.creatorsand.fun>

## 为谁而做

- 希望把自己的数据、内容或自动化能力交给多个 AI 助手使用的个人用户。
- 想用 MCP 快速发布内容、管理轻量数据资产的创作者。
- 希望验证 MCP + OAuth + 多平台连接流程的独立开发者与小团队。

## 当前能力

### 统一账号与连接

- 使用 GitHub 或 Google 登录，账号数据按用户隔离。
- 提供一个统一 MCP endpoint：`https://mcpbuddy.creatorsand.fun/api/mcp`。
- 支持 Claude、ChatGPT/OpenAI 与 Grok 作为连接平台。
- 使用 OAuth 2.1 / PKCE 与动态客户端注册完成兼容平台的授权连接。
- Dashboard 展示各平台的连接状态和连接引导。

### MCP 工具

当前已提供以下工具：

| 工具 | 用途 |
| --- | --- |
| `hello` | 接收来自 Grok、ChatGPT 或 Claude 的问候，并记录该平台连接已验证。 |
| `get_wallet_address` | 返回当前已绑定账户的 Solana 钱包地址。 |
| `get_solana_asset_balances` | 查询绑定钱包中 SOL、USDC、USDT、JUP、BONK 的余额、USD 价格及 USD 估值。 |
| `publish_page` | 将 Markdown 内容发布为公开页或仅自己可见的私有页。 |
| `list_pages` | 读取当前账户已发布的页面列表。 |
| `get_page_content` | 根据页面 ID 或精确标题读取当前账户文章的完整 Markdown 内容。 |

### 内容页面

- 内容格式为 Markdown，并在浏览器端安全渲染（禁用原始 HTML）。
- 公开页面生成可直接访问的分享链接。
- 私有页面仅限发布者登录后访问。
- Dashboard 的 Data · Pages 区域支持查看、打开和删除页面。

### 钱包绑定

- 支持通过 Solana 钱包签名挑战绑定地址。
- 钱包地址是账户属性，供 MCP 工具按当前授权用户读取。
- 钱包绑定不会替代 MCPBuddy 登录，也不承担账户恢复或支付功能。

## 产品流程

```text
GitHub / Google 登录 → 进入 Dashboard → 复制 MCP Endpoint
                              ↓
                 在 Claude / ChatGPT / Grok 添加连接器
                              ↓
                  OAuth 授权并调用 MCP 工具
                              ↓
                 发布页面、读取钱包或扩展个人工具
```

## 技术架构

MCPBuddy 作为 Vercel 应用运行，采用适合无服务器部署的组件组合：

- Next.js：Dashboard、认证回调、OAuth 端点与 MCP Streamable HTTP 服务。
- GitHub OAuth / Google OAuth：用户登录与账户识别。
- Vercel Postgres：用户、OAuth 授权记录、平台连接状态和页面元数据。
- Vercel Blob：公开页面内容等可分享的对象存储。
- MCP TypeScript SDK：标准 MCP 协议处理与工具注册。
- Solana 钱包签名：地址绑定证明。

账号隔离以 OAuth 访问令牌为边界：每次 MCP 请求都会解析授权用户，页面和钱包查询均按该用户范围执行。平台共享同一个 endpoint 并不代表共享身份；每个连接器都应完成各自的 OAuth 授权。

## 当前边界

MCPBuddy 目前是一个个人 MCP 中心的可用初版，而不是通用企业集成平台。以下能力尚未提供或仍需强化：

- 没有团队、组织、成员权限与共享工作区。
- 工具权限目前以账户级授权为主，尚未支持逐工具授权策略。
- 页面没有版本历史、草稿、搜索、标签与回收站。
- 尚未提供用量统计、限流控制台、审计日志和告警。
- Solana 钱包不包含链上交易或签名代理；资产读取仅覆盖 SOL、USDC、USDT、JUP、BONK，且依赖配置的 RPC 与公开行情服务。

## 未来规划

### 阶段一：连接可靠性与可观测性

目标：让连接过程可诊断、可恢复，减少不同 AI 平台之间的兼容成本。

- 增加连接健康检查、最近成功调用时间和错误原因展示。
- 提供每个平台的分步连接向导与复制/重试操作。
- 建立 OAuth 事件与 MCP 调用审计日志，并对敏感字段脱敏。
- 添加按用户和客户端维度的限流、异常检测与基础用量统计。
- 完善 Claude、ChatGPT 和 Grok 的兼容性自动化测试。

### 阶段二：数据与内容能力

目标：把 Pages 从单纯发布工具升级为可被 AI 安全调用的个人知识资产。

- 支持草稿、版本历史、恢复删除和页面搜索。
- 支持标签、元数据、封面及更完整的 Markdown 渲染能力。
- 增加读取单页、更新页面和删除页面等 MCP 工具，并提供明确的确认语义。
- 提供文件上传与引用能力，区分公开 Blob 与私有访问控制。
- 支持内容导入/导出，避免用户数据被锁定。

### 阶段三：可组合的个人工具中心

目标：让用户能将更多私人能力安全地挂载为 MCP 工具。

- 引入工具目录、工具开关、参数说明和权限范围配置。
- 支持连接受控第三方服务，例如 Notion、GitHub、Google Drive 等；每项连接均单独授权与可撤销。
- 支持 Webhook 与后台任务，用于长时间运行的发布、同步和通知工作流。
- 为开发者提供工具模板、测试环境和调用日志。

### 阶段四：协作与商业化

目标：在个人可用的基础上，审慎扩展到团队场景。

- 推出组织、工作区、成员角色与共享资源。
- 增加审批、密钥轮换、数据保留策略与企业审计能力。
- 建立免费层与按连接数、调用量、存储量计费的套餐模型。
- 提供团队级 SLA、导出与管理 API。

## 规划原则

1. **安全优先**：先保证 OAuth、令牌存储、资源隔离与撤销能力，再扩大连接范围。
2. **兼容优先**：遵循 MCP 标准，同时对各 AI 平台的 OAuth 差异采用严格、可测试的适配，不为临时接入放开 redirect URI 校验。
3. **用户拥有数据**：用户应始终能够查看、导出和删除自己的内容与授权。
4. **小步验证**：每个新工具先以最小权限、明确输入输出和可观测日志上线，再根据真实使用扩展。

## 成功指标（建议）

- 新用户从登录到首次成功 MCP 调用的完成率。
- 三个平台的 OAuth 连接成功率与平均授权耗时。
- 每周活跃连接用户数、每用户有效工具调用数。
- 公开页发布成功率与私有页面未授权访问拦截率。
- OAuth/MCP 错误的发现与恢复时间。
